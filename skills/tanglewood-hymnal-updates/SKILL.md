# Tanglewood Hymnal Updates

The Tanglewood Hymnal's MIDI files are provided directly by the hymnal author (LilyPond
exports), not generated by the SYP import pipeline. They identify voices only by channel
(0=soprano, 1=alto, 2=tenor, 3=bass). The app's channel fallback plays them correctly, but
every imported file should be normalized to carry explicit voice trackName events so the
corpus stays uniform and name-based voice lookup works.

## Expected file shape

LilyPond exports are format-1 MIDI: a conductor track whose trackName is the song title
(no notes), then one track per voice — each on a single channel 0–3 in SATB order, with an
`instrumentName` like "acoustic grand" but no trackName. Melody-only songs have one note
track on channel 0 (normalized to `Soprano`).

## Workflow

1. **Copy the author's files** into `~/dev/crescendo/hymnals/Tanglewood Hymnal/` using the
   existing naming convention `<songNumber> - <Title>.mid` (e.g.
   `001.02 - That Man Is Blest Who, Fearing God (IRISH) - Psalm 1.mid`). When replacing an
   existing song, match its current basename exactly.

2. **Normalize track names** — dry-run first, then for real:

   ```bash
   node ~/.claude/skills/tanglewood-hymnal-updates/scripts/add_voice_track_names.mjs \
     --dry-run "~/dev/crescendo/hymnals/Tanglewood Hymnal"
   ```

   The script accepts files or directories (recursive). It inserts a trackName derived from
   each note track's channel, replaces unrecognized names (e.g. `:soprano`), leaves title
   and empty tracks untouched, and verifies each file in memory (identical note/meta/timing
   events, every note track named) before writing. Files it cannot safely normalize (notes
   on multiple channels, channels above 4) are skipped with an error — investigate those
   individually. Already-normalized files are left byte-identical.

3. **Spot-check in the app**: with a dev server running, open
   `http://localhost:<port>/library?songSlug=hymnal/twh2024/song/<songNumber>`
   (song numbers come from the manifest keys, e.g. `3`, not the zero-padded file prefix)
   and confirm the song plays and the voice buttons behave.

4. **Commit and push** the hymnals repo (`git pull --rebase` first — the automation server
   also commits to it). Pushing to main is enough: the automation server's refresh loop
   regenerates manifests, and the changed file hashes invalidate client caches.

## Notes

- The app retains the channel fallback deliberately (see `getVoiceForChannel` in
  `client/src/player/instrument.ts` and `getChannelForVoice` in `common/src/midi_utils.ts`),
  so an unnormalized file still plays — normalization is hygiene, not a hotfix.
- Only `.mid` files need this treatment; author-provided PDFs are copied as-is, and
  Tanglewood songs have `.syp` files but no `.xml` sources (nothing to reimport).
